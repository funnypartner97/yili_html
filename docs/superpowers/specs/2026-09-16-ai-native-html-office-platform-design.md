# AI 原生 HTML 办公产物平台产品方案

日期：2026-09-16  
状态：已完成产品方向确认，进入方案评审  
目标形态：企业内部使用的公有云 SaaS，MVP 为个人使用模式

## 1. 执行摘要

本产品是一个面向企业内部员工的 AI 原生活文档平台。用户上传 PDF、Word、PPT、Excel、CSV、图片或已有 HTML，并通过自然语言描述任务；系统理解材料、生成计划，在用户确认后生成可持续编辑、重组、复用和导出的 HTML 办公产物。

平台以一套统一的结构化文档模型覆盖四种工作模式：演示、文档、数据和看板。四种模式不是四套独立编辑器，而是同一份内容、数据、布局、主题和交互模型的不同呈现方式。

产品长期服务企业内部团队，但 MVP 不做组织空间和多人协作，先验证个人用户能否稳定完成以下核心闭环：

> 上传真实材料 → 描述任务 → 确认生成计划 → 生成活文档 → 对话或直接编辑 → 预览导出 → 保存为个人模板

当前阶段不考虑外部商业化，不设计订阅、定价、销售或公共模板市场。

## 2. 已确认的关键决策

| 议题 | 决策 |
|---|---|
| 长期用户 | 企业内部团队 |
| MVP 用户形态 | 单人使用，不做协作 |
| 产品路线 | 统一活文档平台，而非四套 Office 编辑器 |
| 部署方式 | 公有云 SaaS |
| 新建方式 | 必须基于上传材料或已有模板，不支持无材料空白生成 |
| 自然语言角色 | 作为创建、规划和编辑的交互方式，不作为无材料生成入口 |
| 数据方式 | 使用上传文件中的数据，不连接数据库、API 或 SaaS 数据源 |
| 数据更新 | 用户替换或重新上传数据文件，系统生成新版本或选择性更新 |
| 生成计划 | 每次生成前都展示，允许调整生成参数，并由用户确认 |
| HTML 导入 | 允许用户上传已有 HTML，解析后进入编辑器 |
| 技术内核 | 结构化文档模型 + 受控 HTML 运行时 |
| 商业化 | 当前不考虑，仅用于企业内部 |

## 3. 问题定义

### 3.1 当前状态

企业员工需要在 PPT、Word、Excel、PDF、BI 看板和网页工具之间反复搬运内容。传统办公文件彼此割裂，静态交付难以持续修改和复用；直接让 AI 生成 HTML 虽然快速，但通常存在结构不可控、局部难编辑、版本难管理和模板难沉淀的问题。

### 3.2 期望状态

员工能够把已有材料快速转化为结构清晰、视觉完整、可交互且可继续编辑的 HTML 办公产物。同一份产物可以按不同用途呈现为演示、长文档、数据表或看板，并可沉淀为后续任务使用的模板。

### 3.3 核心差距

- 材料理解与最终产物之间缺少可控的计划确认环节。
- AI 生成的网页通常是一次性代码，不具备稳定的结构化编辑能力。
- 传统模板只约束视觉，无法同时约束内容结构、生成策略和质量标准。
- 多种办公形态缺少统一的内容与组件模型。
- 已有 HTML 难以安全地导入并继续编辑。

### 3.4 产品价值

产品首先减少从材料到可用成果的时间，其次通过模板复用减少重复劳动，最终为企业沉淀可治理的内容生产方法和资产。

## 4. 产品定位

### 4.1 一句话定义

一个把企业材料转化为可编辑、可复用 HTML 办公成果的 AI 原生活文档平台。

### 4.2 核心表达

> 先把材料变成成果，再把成果沉淀为模板。

不建议在早期宣传“替代全部 Office”。对内部用户应强调：上传现有材料，快速生成一份可以继续修改和交付的成果。

### 4.3 工作模式

| 模式 | 主要用途 | 典型产物 |
|---|---|---|
| 演示 | 讲述、汇报、培训 | 项目汇报、经营复盘、培训课件 |
| 文档 | 阅读、论证、归档 | 研究报告、总结、制度说明 |
| 数据 | 整理、计算、分析 | 明细表、分析表、基础模型 |
| 看板 | 概览、筛选、决策 | 经营看板、项目驾驶舱 |

四种模式可以混合存在。例如一份经营报告可以同时包含长文分析、数据表、交互图表和全屏演示页面。

## 5. 产品原则

1. **材料优先**：所有新生成任务必须有材料或模板依据。
2. **计划先行**：每次生成前展示结构、篇幅、模板和材料使用计划。
3. **结构化优先**：AI 修改结构化文档模型，而不是反复重写整页代码。
4. **对话与直编并存**：用户既能直接编辑，也能通过 AI 修改选中范围或全文。
5. **来源可回溯**：重要内容应能回到原始材料位置。
6. **修改可恢复**：AI 修改明确影响范围，并支持撤销和版本恢复。
7. **兼容但不承诺无损**：导入 HTML 时清楚标记可编辑程度。
8. **统一内核、渐进能力**：四种模式共用内核，但 MVP 不追求同时达到传统专业工具的全部深度。

## 6. 用户与场景

### 6.1 MVP 用户

MVP 面向企业内部高频制作办公材料的个人员工，优先包括战略、经营分析、总经办、产品、运营、市场、研究、数据分析和内部培训人员。

### 6.2 MVP 高频场景

1. 上传多份材料，生成结构完整的汇报或报告。
2. 选择企业或个人模板，用新材料生成同类产物。
3. 上传 Excel 或 CSV，生成分析表、图表和交互看板。
4. 上传已有 HTML，转换为可编辑活文档。
5. 替换材料或数据文件，生成新版本或选择性更新旧产物。
6. 在编辑器内通过对话修改内容、结构、视觉和组件。
7. 将优秀产物保存为个人模板。

## 7. 信息架构

MVP 保留轻量的个人产品结构，不设置企业工作空间模块。

### 7.1 一级页面

- **首页**：对话式创建入口、最近产物和快捷模板。
- **我的产物**：个人产物列表、搜索、复制、归档和删除。
- **模板库**：平台模板和个人模板。
- **统一编辑器**：内容编辑、组件配置、AI 对话、预览和导出。
- **设置**：个人偏好、文件处理和模型相关提示。

### 7.2 首页入口

首页中央提供显著的任务对话框。用户可以描述目标，同时添加材料或选择模板；未添加材料或模板时不能开始生成。

首页还提供两个明确入口：

- 上传已有 HTML 并进入编辑器。
- 从模板开始，再补充该模板要求的材料。

### 7.3 编辑器布局

- 左侧：章节、页面或数据表导航。
- 中央：当前文档、画布、表格或看板编辑区域。
- 右侧：AI 对话、组件属性、来源与质量提示。
- 顶部：模式切换、预览、历史版本、导出和另存为模板。

## 8. 端到端用户流程

### 8.1 创建

用户输入用途、受众和要求，并上传材料或选择模板。系统立即显示材料清单、解析进度和失败文件。

### 8.2 理解与计划

系统解析材料，生成一份每次都必须确认的制作计划，包括：

- 产物形态和工作模式，允许多选并组合生成。
- 内容大纲和预计篇幅。
- 已解析材料的摘要、异常和内容冲突提示。
- 采用的模板和视觉主题。
- 将生成的表格、图表或交互组件。

用户可以调整结构、产物形态、受众、篇幅、密度、模板和输出规格，然后确认生成。上传到当前任务的材料默认全部参与理解。

#### 8.2.1 生成参数

生成参数是制作计划的一部分，由 AI 根据用户描述和材料自动预填。用户修改参数后再确认生成，不需要在进入计划页之前填写独立表单。

首屏默认展示以下参数：

| 参数 | 规则与选项 |
|---|---|
| 产物形态 | 多选；可组合演示、文档、数据和看板 |
| 目标受众 | 管理层、专业人员、普通员工或自定义 |
| 篇幅 | 精简、标准、详细，或指定页数、章节数 |
| 内容密度 | 留白型、均衡型或信息密集型 |
| 视觉模板 | 平台模板、个人模板或沿用导入 HTML 的主题 |
| 输出规格 | 16:9、4:3、A4 或响应式网页 |
| 重点内容 | 指定必须突出、保留或优先呈现的内容 |

参数按产物形态动态扩展：

- 数据或看板：工作表、指标、维度、数据处理权限、图表偏好和交互程度。
- 文档或演示：表达语气、原文保留程度、摘要深度、引用展示和图片策略。
- HTML 导入：优先保留视觉或优先提高可编辑性、目标规格、组件提炼和主题提炼。

高级参数默认折叠，包括字体与间距、动画强度、数字格式、原文改写程度、材料冲突策略、更新材料时保护人工修改，以及导出资源打包方式。

用户可以将常用参数组合保存为“生成预设”。生成预设控制受众、篇幅、密度和处理策略；模板控制内容结构、组件、视觉、生成规则和质量规则，二者分别管理。

### 8.3 渐进生成

系统先生成文档骨架，再逐页或逐章节填充内容与视觉。已经完成的页面可以提前进入编辑器，生成中断时保留已完成内容并从失败节点恢复。

### 8.4 编辑

编辑方式包括：

- 直接编辑文字、数据、布局和组件属性。
- 选中组件后要求 AI 局部改写、重算或重新设计。
- 通过右侧对话栏调整全文结构、风格或材料使用方式。

所有 AI 修改先展示影响范围，执行后可以撤销或恢复旧版本。

### 8.5 交付与复用

用户可以在阅读、演示或交互模式预览，导出独立 HTML、PDF 或图片，也可以复制产物或保存为个人模板。

## 9. MVP 功能范围

### 9.1 材料处理

- 上传 PDF、Word、PPT、Excel、CSV、图片和 HTML。
- 提取文本、表格、图片、基本版面和文件结构。
- 同一任务组合多份材料。
- 展示材料解析状态、失败原因和内容来源。
- 替换材料并创建新版本。

### 9.2 AI 生成

- 根据材料和用户描述生成制作计划。
- 每次由用户确认计划后再生成。
- 生成演示、文档、数据和看板四种模式。
- 支持全文与局部对话修改。
- 生成前后执行材料完整性、引用和版面检查。

### 9.3 统一编辑器

- 块级内容编辑和页面、章节管理。
- 文档流、自由画布和网格布局。
- 表格、基础公式、图表和筛选组件。
- 主题、字体、颜色、间距和版式设置。
- 阅读、演示、编辑和交互预览。
- 历史版本、撤销和恢复。
- 上传 HTML 后直接启用编辑器。

### 9.4 模板

- 平台预置模板和个人模板。
- 从活文档另存为模板。
- 从导入 HTML 中提炼模板。
- 单独套用视觉主题，或同时复用内容结构。

### 9.5 导出

- 平台内预览。
- 导出独立 HTML、PDF 和图片。
- MVP 不承诺高保真导出为 PPTX、DOCX 或 XLSX。

### 9.6 MVP 明确不做

- 无材料的空白提示词生成。
- 数据库、API 或 SaaS 数据源连接。
- 自动实时数据刷新。
- 企业工作空间、成员、权限、评论和多人协作。
- 完整 Office 高级功能与双向兼容。
- 任意 JavaScript 执行环境。
- 公共模板市场。
- 定价、订阅、销售和外部商业化能力。

## 10. 统一活文档模型

平台的核心对象不是一段 HTML，而是可验证的文档图谱：

```text
活文档
├── 元信息：标题、模式、来源、创建时间
├── 内容树：章节、页面、文本、图片、引用
├── 数据模型：数据表、字段、公式、图表、筛选
├── 布局模型：文档流、画布、网格、响应式规则
├── 组件树：内容、数据、交互和导航组件
├── 主题系统：字体、颜色、间距、版式
├── 来源映射：组件与原始材料位置的关系
└── 命令与版本：修改操作、撤销、历史快照
```

四种工作模式是文档图谱的视图策略，而不是互相隔离的文件类型。

## 11. 模板体系

每个模板由五层组成：

1. **内容结构**：章节、页面、信息层级和必填内容。
2. **组件配置**：允许使用的文字、表格、图表和交互组件。
3. **视觉主题**：字体、颜色、间距、版式和品牌元素。
4. **生成规则**：每个区域应从材料提取什么以及如何组织。
5. **质量规则**：篇幅、字数、数据完整性、溢出和引用检查。

模板不是静态 HTML 文件。模板实例化后产生结构化活文档，用户可以在允许范围内修改内容和样式。

## 12. AI 生成机制

### 12.1 生成链路

```text
文件解析
  ↓
材料理解与来源索引
  ↓
生成制作计划
  ↓
用户确认
  ↓
结构与组件规划
  ↓
内容、数据与布局生成
  ↓
引用、完整性和视觉质量校验
  ↓
进入统一编辑器
```

### 12.2 修改机制

AI 输出结构化操作命令，例如插入章节、替换文本、更新表格、变更主题或重新布局。文档内核验证命令合法性后执行，避免模型直接重写整份 HTML。

### 12.3 质量规则

- 未在材料中找到依据时明确提示，不自动虚构。
- 材料冲突时列出冲突位置并让用户选择依据。
- 图表必须能回溯到上传数据表和字段。
- 内容更新与人工结论分开，替换材料时不默认覆盖人工修改。
- 检测文字溢出、组件遮挡、空页面和不可读配色。

## 13. HTML 导入策略

### 13.1 安全处理

- 清理脚本、内联事件、危险 URL 和不可信嵌入。
- 对外链字体、图片和样式应用明确的资源策略。
- 禁止未经授权的网络请求和任意代码执行。

### 13.2 转换结果

导入结果分为三类：

- **原生可编辑**：识别为平台内容、布局或数据组件。
- **有限编辑**：保留结构，可编辑文字和部分样式。
- **仅预览**：放入受限沙箱 HTML 块，不能使用完整可视化编辑能力。

系统生成兼容性报告，明确每个区域的类别和风险。MVP 不承诺任意 HTML 无损转换。

## 14. 技术架构

### 14.1 客户端

- 首页与创建对话框。
- 生成计划确认界面。
- 统一编辑器和四种视图。
- 版本历史、预览和导出界面。

### 14.2 文档内核

- 文档图谱与 Schema 校验。
- 组件注册和受控运行时。
- 命令系统、撤销重做和版本快照。
- 主题与布局引擎。
- 来源映射与引用追踪。

### 14.3 AI 编排

- 文件内容理解。
- 制作计划生成。
- 结构、内容、数据和布局生成。
- 对话修改到结构化命令的转换。
- 事实、完整性和视觉质量检查。

### 14.4 后端服务

- 身份认证和个人项目存储。
- 文件上传、解析和对象存储。
- 生成任务调度、重试和进度事件。
- 模板管理。
- HTML、PDF 和图片渲染导出。
- 使用日志、错误监控和生成成本统计。

### 14.5 核心数据流

上传文件进入隔离存储，经解析服务生成标准化内容和来源索引。AI 编排服务基于这些内容生成制作计划；用户确认后生成文档图谱。编辑器加载文档图谱，所有修改以命令形式写入并产生版本。导出服务使用受控运行时渲染最终 HTML，再按需转换为 PDF 或图片。

## 15. 错误处理与恢复

| 异常 | 产品处理 |
|---|---|
| 文件无法解析 | 指明具体文件和原因，允许移除或重新上传 |
| 材料不足 | 标记无法生成的章节，不填充虚构内容 |
| 材料冲突 | 展示冲突来源，由用户选择或保留差异说明 |
| 生成中断 | 保留已经完成的节点，从失败节点继续 |
| 组件生成失败 | 使用安全降级组件并允许单独重新生成 |
| HTML 无法转换 | 保留为隔离预览块，并生成兼容性报告 |
| 导出失败 | 保留可编辑文档，重试导出，不重复生成内容 |
| AI 修改效果不佳 | 支持撤销、版本对比和恢复 |

## 16. 测试与质量保障

### 16.1 材料解析

- 建立覆盖常见、复杂和损坏文件的样本库。
- 检查文字、表格、图片、页码和来源位置的提取准确性。

### 16.2 文档模型

- 对 Schema、命令、撤销重做和版本迁移进行自动化测试。
- 确保四种视图不会破坏同一份底层内容。

### 16.3 生成质量

- 用固定任务集评估内容完整性、引用准确性、图表数据一致性和视觉溢出。
- 记录用户完全重做、局部修改和直接采用的比例。

### 16.4 HTML 安全

- 使用包含脚本、事件、危险链接和外链资源的测试集。
- 验证沙箱隔离、内容安全策略和网络请求限制。

### 16.5 导出

- 对不同字体、页面比例、长文档、图表和交互降级进行回归测试。

## 17. 版本路线图

### 阶段一：MVP，个人创作闭环

- 材料和 HTML 上传解析。
- 对话式创建和每次计划确认。
- 四种模式的基础生成能力。
- 统一编辑器、右侧 AI 对话和版本恢复。
- 预置模板、个人模板和从 HTML 提炼模板。
- HTML、PDF 和图片导出。

### 阶段二：质量与资产复用

- 增强行业场景模板和模板编辑器。
- 材料替换、差异对比和选择性更新。
- 更强的来源、事实与视觉质量校验。
- 提升 HTML 导入和 Office 导出兼容性。
- 管理个人素材、组件、主题和模板资产。

### 阶段三：企业协作与治理

- 组织、团队和项目空间。
- 成员角色、内容权限和企业模板发布。
- 评论、批注、修改建议、审批和发布。
- SSO、审计、内容策略、模型与成本管理。
- 企业级使用分析和运营治理。

## 18. MVP 成功指标

### 北极星指标

每周完成并导出的有效产物数。有效产物是指完成生成后至少发生一次编辑或确认，并进入预览或导出环节的产物。

### 建议观察指标

- 首次有效产物完成率。
- 从上传材料到得到可编辑结果的中位时间。
- 生成后发生直接编辑或 AI 修改的比例。
- 产物被实际用于内部汇报或沟通的比例。
- 四周内再次创建产物的用户比例。
- 旧产物或个人模板复用率。
- 因事实或版面问题完全重做的比例。
- 单份产物的平均生成时间、模型成本和失败率。

指标首先用于比较产品迭代前后的变化，不作为对员工的绩效考核。

## 19. 内部试点与治理

### 19.1 推进方式

1. 选择 10–20 名高频制作材料的员工进行小范围试点。
2. 使用真实、合规的内部材料完成完整任务，不只测试演示样例。
3. 每周评审失败案例、完全重做案例和高复用产物。
4. 核心体验稳定后，为高频部门沉淀专属模板和主题。
5. 最后进入企业空间、权限与治理能力建设。

### 19.2 责任划分

- 产品运营：管理试点、收集需求和定义优先级。
- 模板负责人：维护模板、视觉规范和示例产物。
- 技术团队：负责编辑器、生成链路和稳定性。
- AI/安全负责人：管理模型、文件策略和内容风险。
- 业务种子用户：提供真实材料、验证结果和沉淀最佳实践。

### 19.3 治理底线

- 明确文件存储位置、访问范围和保留期限。
- 区分普通、敏感和禁止上传的材料。
- 明确模型提供方是否保留或训练企业数据。
- HTML 导入必须经过安全清理和沙箱隔离。
- 生成结果由使用者完成最终确认。
- 所有材料版本和 AI 修改可以回溯。

## 20. 主要风险与应对

| 风险 | 应对方式 |
|---|---|
| 四种模式导致范围失控 | 共用文档和组件内核，接受 MVP 能力深度不同 |
| 生成内容不可信 | 严格依赖材料，保留来源，不足和冲突时显式提示 |
| HTML 导入预期过高 | 提供兼容性报告和三档编辑能力 |
| 编辑器与 AI 修改互相破坏 | 使用结构化命令、影响范围预览和版本恢复 |
| 等待时间过长 | 缓存解析结果、渐进生成、允许提前编辑已完成部分 |
| 模型成本过高 | 按任务拆分模型等级，缓存材料理解和中间结果 |
| 模板只有视觉价值 | 同时定义内容结构、生成规则和质量规则 |
| 内部推广依赖行政推动 | 以实际交付时间和复用率验证自发价值 |

## 21. MVP 验收条件

MVP 可以进入内部试点，需要同时满足以下条件：

1. 用户能从材料或模板创建任务，且无法在无材料、无模板时生成。
2. 每次生成都会显示计划，并允许用户调整后确认。
3. 系统能生成并编辑四种模式的基础产物。
4. 用户能在编辑器内直接编辑并通过右侧对话修改。
5. AI 修改支持撤销和版本恢复。
6. 用户能上传 HTML，并得到可编辑程度与安全处理报告。
7. 用户能将产物保存为个人模板。
8. 用户能导出独立 HTML、PDF 和图片。
9. 材料不足、冲突、解析失败和生成中断都有明确恢复路径。
10. 文件处理、HTML 隔离和模型数据策略通过内部安全评审。

## 22. 结论

本产品不应从“同时复制 PPT、Word、Excel 和 BI”出发，而应首先建立统一活文档内核。用户看到的是熟悉的四种工作模式，底层则是同一套内容、数据、布局、模板和版本模型。

MVP 的胜负不在于功能数量，而在于能否稳定完成一条可信闭环：基于真实材料生成计划清晰、结果可编辑、来源可追溯、能够交付并可以复用的办公产物。只要这条闭环成立，后续的企业协作、模板治理和组织资产沉淀才有建设价值。
